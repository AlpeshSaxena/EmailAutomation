The Netlify deploy errored, with the following guidance provided:

Diagnosis
- The install fails because pnpm refuses to do a frozen installation when the lockfile and your package configuration disagree. The pnpm error is shown at [line 22](#L22) and pnpm even suggests the fix at [line 23](#L23). The build aborts during dependency installation ([line 18](#L18), [line 24](#L24), [line 25](#L25)).
- Netlify also detected a pnpm version difference and prepared pnpm@9 for the build ([line 17](#L17)); this means you should update the lockfile with the same pnpm toolchain that Netlify uses (or make Netlify use the same pnpm you used locally).
- There is also a warning that NODE_ENV is set to production so devDependencies won’t be installed ([line 16](#L16)). That’s not the immediate failure, but could cause missing build tools later if your build needs devDependencies.

Solution
1) Regenerate and commit an updated lockfile (recommended)
- Locally, ensure you run pnpm using a version compatible with what the build expects. Netlify prepared pnpm@9.15.9 in the logs; you can activate that locally:
```bash
# using corepack (recommended)
corepack prepare pnpm@9.15.9 --activate

# or install globally (alternative)
npm install -g pnpm@9.15.9
```
- Regenerate the lockfile (this matches the suggestion in the logs):
```bash
pnpm install --no-frozen-lockfile
```
- Review changes, then commit the updated pnpm-lock.yaml (and package.json if it changed):
```bash
git add pnpm-lock.yaml package.json
git commit -m "Regenerate pnpm lockfile to match overrides/config"
git push
```
- Trigger a Netlify rebuild. The frozen install error should be resolved because the lockfile now matches package configuration.

2) If you intentionally want to keep the lockfile unchanged
- Revert whatever change introduced the mismatch (for example, ensure package.json "overrides" matches the lockfile). Then commit and push so the lockfile and package.json are consistent.

3) (Optional) If your build needs devDependencies
- If your build requires devDependencies to be installed, either move the required items from devDependencies to dependencies or configure Netlify to install them by changing the build environment variable:
- In Netlify UI > Site settings > Build & deploy > Environment, set NODE_ENV = development
- Or add to netlify.toml:
```toml
[build.environment]
  NODE_ENV = "development"
```
Note: Netlify sets NODE_ENV=production by default ([line 16](#L16)), which will skip devDependencies during install.

4) Verify pnpm version consistency (recommended)
- Ensure you and CI use the same pnpm major version. Use corepack to pin the project pnpm version or document the required pnpm version for contributors/CI. This avoids subtle differences when generating lockfiles (the logs show Netlify adjusted pnpm to v9 to match expected [line 17](#L17)).

After regenerating and committing the updated lockfile, rebuild on Netlify. If you still see the same error, run a local check:
```bash
pnpm install --frozen-lockfile
```
If that fails locally, the problem must be corrected locally (package.json vs lockfile) before Netlify can install dependencies successfully.
